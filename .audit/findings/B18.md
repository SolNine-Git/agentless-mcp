### B18-H1 — `find_referencing_symbols` truncates fan-in silently and positionally, on the tool whose whole purpose is blast radius

`src/agentless_mcp/application/symbol_service.py:243-260`

```python
sites = _dedupe(
    site for definition in definitions for site in refs.references_to(index, definition)
)
...
groups = _group_sites(sites[:limit], by_path, resolver, target_ids)
...
return RefsResult(target=target, groups=groups, total=len(sites), limit=limit, shared=shared)
```

`_dedupe` returns sites sorted by `(path, line, name)` (`:434-437`), so `sites[:limit]` keeps the alphabetically-first files and drops the rest **whole**. `RefsResult` carries `total` and `limit` so a consumer can report the loss, but no text consumer does: `render.render_ref_groups` computes its own header from `sum(len(group.sites) for group in groups)` (`render.py:788-789`), and both adapters call it with the groups alone —
`adapters/mcp/server.py:295` and `adapters/cli/main.py:736`.

Measured on a 27-file repository with 52 reference sites across 26 caller files, `limit=10`:

```
service total: 52  limit: 10  groups: 5
rendered header: "10 references to widget"
files present in text: ['a_mod.py','b_mod.py','c_mod.py','d_mod.py','e_mod.py']
z_mod.py in text? False
any omission marker? False
```

Twenty-one of twenty-six caller files vanish and the answer asserts a total of 10. The wire description the model reads says the opposite — `prompts/tool_descriptions.json`, `find_referencing_symbols`: *"Every name match is still listed"* — and the neighbouring `shared_callers` half of the same sentence *is* honest (`SharedCallerListing.omitted`). The module docstring of the dependency states the doctrine this violates (`core/refs.py:14`): *"it never silently under-reports, which is the failure mode that matters for a blast-radius question."*

**Failure scenario.** An agent runs `find_referencing_symbols` on a function it is about to change signature on, sees ten callers in five files, updates them, and ships. The twenty-one callers in files sorted after `e_mod.py` are never seen, and nothing in the answer suggested there were any. This is the exact class of defect `render_expansion` was created to prevent — its own docstring (`:375-377`) says *"an adapter that printed the cards without the shortening summary would be the silent-truncation defect back in a different file."*

**Recommendation.** The mechanism already exists and is documented for this case: `envelope.wrap(..., truncation=Truncation(shown, total, unit))` — *"what the service already left out (symbols past a budget, matches past a limit)"* (`envelope.py:118-125`). Today only `repo_map` passes it (`server.py:226`, `cli/main.py:642`). Give this block the same treatment it gave expansion: add a `render_references(result: RefsResult) -> str` beside `render_expansion` in this file that prints `result.total`, the number of files omitted entirely, and the limit, so no adapter can drop it — and have both adapters call that instead of `render.render_ref_groups`. Separately, consider whether truncation should be per-file round-robin rather than `sites[:limit]`: the file already argues (`:9-18`) that positional degradation is the wrong shape when the caller asked about a set.

### B18-H2 — one unwarmed grammar aborts the entire expand batch instead of degrading that id

`src/agentless_mcp/application/symbol_service.py:354-360`

```python
language = TreeSitterExtractor.SUPPORTED_EXTENSIONS.get(absolute.suffix)
if language is None:
    return None, f"{parsed.path}: no grammar for this file type"

symbols = effective_source(ctx.symbols, self._extractor).symbols_for(
    read.text, language, parsed.path
)
```

`_expand_one` catches `ValueError` (`:340`) and `SecurityRefusal` (`:346`) and handles a `None` read (`:351`) and an unsupported suffix (`:355`) — but a *supported* suffix whose grammar is not warmed raises `LanguageUnavailable` straight through `symbols_for` → `extract_from_source` → `grammars.get_language` (`core/grammars.py:187`). Reproduced by hiding the ruby grammar and expanding a two-id batch:

```
LanguageUnavailable: language 'ruby' not warmed: run agentless-mcp warmup
  File ".../symbol_service.py", line 207, in expand_symbols
  File ".../symbol_service.py", line 358, in _expand_one
```

The `py:a.py::alpha` card had already been built successfully and was discarded with the exception. `core/refs.py:236-238` handles precisely this error for exactly this reason (`"degrading that file alone when it cannot be"`), so this file is the one that broke the convention, not the one that set it. It also breaks the invariant this module's own docstring asserts twice (`:17-18`, and the `expand_symbols` tool description): *"Every requested id comes back."*

**Failure scenario.** A polyglot repository is indexed but `warmup` only fetched the tier-1 grammars. An agent expands ten ids from a `repo_map`, one of which lands in a `.rb`/`.swift`/`.kt` file; the MCP tool raises, the agent gets a protocol-level error rather than nine bodies plus one named degradation, and has no way to tell which id poisoned the call.

**Recommendation.** Add `LanguageUnavailable` to the handled errors in `_expand_one`, returning `(None, str(exc))` so the id lands in `unresolved` with the actionable `run agentless-mcp warmup` text — the same shape `refs._parse_one` uses. Pin it with a test that monkeypatches `grammars.warmed_languages`.

### B18-H3 — the `EXPAND_MAX_SEATS` justification is a measured claim that does not hold; the unresolved flood is charged against no budget

`src/agentless_mcp/application/symbol_service.py:82-90` and `:213-219`

```python
# ... 40 is four times the documented per-call limit and was verified to leave
# the wrapped JSON clear of the ceiling at 40, 60 and 192 requested ids.
EXPAND_MAX_SEATS = 40
```

```python
for raw in stable_ids[limit:]:
    unresolved.append((raw, f"not expanded: the per-call limit is {limit} symbols"))

if len(cards) > seats:
    reason = MESSAGES.expand_no_room.format(requested=len(cards), seats=seats)
    unresolved.extend((card.stable_id, reason) for card in cards[seats:])
```

`_fit_bodies` budgets the *cards* at 12 000 tokens (`:73`), leaving a stated ~4 000-token margin under the envelope's `DEFAULT_MAX_TOKENS = 16_000` (`envelope.py:49`). Nothing budgets the unresolved list, which grows one ~22-token line per id past the seats and per id past `limit`. Measured on a repo of 400 120-line functions:

```
n=192 cards=40 unresolved=152 body_tokens=17433 text_truncated=True  json_truncated=True  json_symbols=26
n=400 cards=40 unresolved=360 body_tokens=23829 text_truncated=True  json_truncated=True  json_symbols=3
```

At the very id count the comment names as verified (192), the JSON envelope drops 14 of the 40 seated cards, and at 400 it drops 37 of 40 — dropping *whole symbols*, which the comment itself identifies as *"precisely the failure the fair split exists to prevent."* The text form is truncated too. `limit` is a bare `int` on the wire (`server.py:540`) with no `Field` constraint, so a model holding 400 ids reaching for `limit=400` is a supported call.

**Failure scenario.** An agent that has just read a `repo_map` asks to expand everything it saw, raising `limit` to match. It receives three bodies out of forty seats plus 360 lines of boilerplate refusal — a strictly worse answer than the ten-id default would have given, produced by the machinery built to make over-asking safe.

**Recommendation.** Charge the unresolved list against the same ceiling: cap the unresolved entries the render emits (e.g. list the first N raw ids and then a single `"... K more ids were not expanded"` line, the shape `render_shared_callers` already uses), and compute the card budget as `ceiling - header - unresolved_cost` rather than as the fixed 12 000. Re-measure before restating the "verified at 40/60/192" claim in the comment, or delete the claim — a comment asserting a measurement that fails is worse than no comment, since the next maintainer reads it as a reason not to re-test.

### B18-M2 — `limit=0` turns both listings into a confident false negative

`src/agentless_mcp/application/symbol_service.py:190`, `:248`; wire types at `server.py:540, 568, 583`

No call validates `limit`, and the MCP tools declare it as a bare `int`. Measured against a repo with 26 matches and 52 reference sites:

```
find_symbol(limit=0)  -> text: "no matching symbols"                                (total=26)
find_referencing_symbols(limit=0) -> text: "no references to widget outside its own definition"  (total=52)
```

A negative limit is worse: `stable_ids[:-1]` in `expand_symbols` (`:206`) expands everything except the last id and reports the last as *"not expanded: the per-call limit is -1 symbols"*.

**Failure scenario.** A model that computes a limit arithmetically (`limit = remaining_budget // cost`, `limit = len(ids) - already_seen`) and lands on 0 is told the symbol has no callers at all — the answer this module's dependency calls *"the most expensive wrong answer this tool could give"* (`core/extractor.py:449-452`).

**Recommendation.** Clamp at the service boundary (`limit = max(1, limit)` or reject with a named reason) rather than at the adapter, since the CLI is a second caller of the same signature; the boundary this file owns is the service method, not the wire.

### B18-M5 — the adjacency ranking is core domain work living in the application layer

`src/agentless_mcp/application/symbol_service.py:492-641`

`_Adjacency` plus `_shared_callers` is ~150 lines of graph-scoring algorithm — caller-set construction, per-file max-vote reduction, log damping of name spread and caller fan-out, stoplist multipliers, production-before-test ordering — that manipulates nothing but `core.refs` and `core.symbols` values and reaches into `core.graph` for two of its three corrections (`graph.common_name_damping`, `graph.name_multiplier`). Its own docstring concedes the placement problem: *"each is the treatment `agentless_mcp.core.graph` already applies to the same problem."* `_defined_in_tests` (B18-M3) is the same shape: a repository-structure heuristic with no application-layer dependency at all.

This is the concrete content behind the block's Ce=12 / instability 0.75: the service imports `render`, `repo_context`, `cache`, `extractor`, `graph`, `refs`, `resolve`, `symbols`, `prompts`, `fslimits`, `errors`, `tokens` — and roughly a third of the file would compile against `core` alone. The file *is* deep at the boundary (three public methods over 646 lines), so this is not an over-engineering finding; it is a "depend toward stability" one — the ranking rules are the stable part and they sit in the unstable layer.

**Recommendation.** Move `_Adjacency`, `_shared_callers` and `_defined_in_tests` into `core.graph` (or a `core.adjacency` beside it), where the two damping functions they already borrow live, and leave `find_referencing_symbols` orchestrating: scan, index, resolve, rank, render. This is also what makes B18-M3 testable without standing up a repository fixture.

### B18-L2 — `_group_sites` maintains a per-path dict whose values are always the same string

`src/agentless_mcp/application/symbol_service.py:447-462`

```python
names: dict[str, str] = {}
...
names.setdefault(site.path, site.name)
...
_ref_group(path, tuple(grouped[path]), names[path], resolver, target_ids)
```

Every site reaching here came from `refs.references_to(index, definition)`, which returns `index.sites.get(symbol.name)` for definitions all keyed by one name (`core/refs.py:167-198`). So `names` maps every path to the identical string. The name is already available as the caller's `target`/`definitions[0].symbol.name`.

**Recommendation.** Drop the dict and pass the single name through. It removes a per-path allocation and, more usefully, removes the suggestion that a group's sites might spell different names — a reader currently has to prove that they cannot.

### B18-L3 — duplicate stable ids expand twice and consume two seats and two budget shares

`src/agentless_mcp/application/symbol_service.py:206-220`

Nothing de-duplicates `stable_ids`. `expand_symbols(ctx, ["py:a.py::f", "py:a.py::f"])` reads and parses the file twice, returns two identical cards, and both compete in `_fit_bodies` — so a batch with repeats gets every body cut smaller than it needed to be. Contrast `_dedupe` (`:434-437`), which the refs path applies for the same reason.

**Recommendation.** De-duplicate while preserving first-seen order before the expand loop, so a retrying or list-concatenating caller cannot halve its own budget.

### B18-L4 — the same file is read and re-parsed once per requested id

`src/agentless_mcp/application/symbol_service.py:350-360`

`_expand_one` calls `read_bounded` and `symbols_for` per id, so expanding ten methods of one class reads and parses that file ten times. Measured at ~2 ms per id on this repository — immaterial at the default `limit=10`, linear in a caller-supplied limit (see B18-H3, where 400 ids trigger 400 parses of one file only to discard 360 of the results at the seats cut).

**Recommendation.** Group `stable_ids` by `parsed.path`, read and parse each path once, then resolve every requested qualname against that one symbol list. This also makes the seats cut cheap: apply it before the parsing rather than after.

### B18-L5 — module docstring states a cap the code treats as a default

`src/agentless_mcp/application/symbol_service.py:6-7`

> *"`expand_symbols` is the escalation, capped at ten bodies so it stays an escalation rather than a second way to read the repository."*

`DEFAULT_EXPAND_LIMIT = 10` is a default parameter that any caller overrides (`server.py:540` exposes it directly on the wire, unconstrained). The real cap is `EXPAND_MAX_SEATS = 40`. Per Pass 1, a comment asserting an invariant the code does not hold is read literally by the next agent generating against it — here it would justify not validating `limit`, which is B18-M2.

**Recommendation.** Say "ten by default, hard-capped at forty seats", or make ten a real cap.

## Cross-block observations

* **The `envelope.Truncation` mechanism is documented for "matches past a limit" and used by exactly one of the six limited listings.** Only `repo_map` passes it (`adapters/mcp/server.py:226`, `adapters/cli/main.py:642`). `find_symbol`, `find_referencing_symbols`, `list_dir` (`max_entries`), `get_symbols_overview` and `explain_symbol` all take a limit and none of them passes a `Truncation`. Worth a cross-block sweep of every `limit=` parameter in the adapter blocks against whether its overflow reaches the text answer — B18-H1 and B18-M1 are probably instances of a family, not two isolated bugs.
* **Text and JSON renderings disagree about honesty in a systematic direction.** `FindResult.as_dict()` and `RefsResult.as_dict()` carry `total` and `limit`; the text forms carry neither. Every MCP tool returns text. Whoever owns the `render` block (B16?) should be asked whether "the JSON is the honest form" is a decision or an accident — `_Answer` in `cli/main.py:1322-1327` explicitly claims the two forms *"cannot diverge by accident"*, which is not true of these two.
* **Error-degradation conventions are set in `core.refs` and not followed in `application`.** `refs._parse_one` catches `LanguageUnavailable` per file; `symbol_service._expand_one` does not (B18-H2). Worth grepping every `symbols_for` / `imports_for` / `refs_for` call site outside `core.refs` for the same omission — `view_service` and `graph_service` are the likely siblings.
* **`limit` is an unconstrained bare `int` on every MCP tool.** No `Field(ge=1)` anywhere in `adapters/mcp/server.py`. B18-M2 is the symbol-service instance; the wire-validation question belongs to the adapter block.
* **Multi-language claims are asserted per-feature but verified only for Python and Go.** `_defined_in_tests` (B18-M3) promises language-neutral behaviour and delivers Python/Java. The characterization fixtures are `repo_py`, `repo_ts`, `repo_go`; the tier-2 languages (`ruby`, `swift`, `kotlin`, `php`, `lua`, `rust`) have grammar tests but no behavioural fixtures. Worth a cross-block count of features that claim to be language-agnostic versus features with a fixture in more than one language.
