## High

### B06-H1 — `get_parser` constructs the `Parser` outside every handler, so a broken grammar escapes as an untyped `ValueError` and is swallowed downstream as "unsupported language"

`src/agentless_mcp/core/grammars.py:196-199`

```python
@cache
def get_parser(name: str) -> Parser:
    """Return a memoized parser for ``name``. Never fetches."""
    return Parser(get_language(name))
```

The only handler in this module is the one at lines 189-193, and it wraps `pack.get_language` only. `Parser(language)` is where the tree-sitter binding enforces the grammar ABI: `strings .venv/lib/python3.13/site-packages/tree_sitter/_binding.cpython-313-x86_64-linux-gnu.so` shows `Incompatible Language version %u. Must be between %u and %u`, and `tree_sitter.LANGUAGE_VERSION == 15`, `MIN_COMPATIBLE_LANGUAGE_VERSION == 13` on the installed 0.26.0. Whatever the exact type, line 199 is outside any `try`, so *any* parser-construction failure leaves this module untyped.

That directly contradicts the module's own contract, stated at lines 12-14:

> `get_language` never fetches. A grammar that is not already on disk produces `LanguageUnavailable` naming the remediation.

and at `src/agentless_mcp/core/skeleton.py:96` ("Raises `LanguageUnavailable` (from `agentless_mcp.core.grammars`)").

Failure scenario: a `tree-sitter` minor bump (the pin is `tree-sitter>=0.25,<0.27`, so 0.25→0.26 moves inside the range) shifts the compatible ABI window past a cached grammar's version. `pack.get_language` still succeeds — it returns a `Language` handle without checking ABI, confirmed: `pack.get_language("shell")` returns `<Language id=..., version=14, name=None>` — and the failure lands on `Parser(...)`. Every caller is written against `LanguageUnavailable`: `core/normalize.py:184-186` catches only `LanguageUnavailable` and would propagate the `ValueError` out of a validate run; worse, `core/extractor.py:681-685` and `:725-729` do

```python
try:
    parser = self.get_parser(language)
except ValueError as e:
    logger.warning("Unsupported language %s (%s): %s", language, module_path, e)
    return []
```

so an ABI-incompatible grammar is logged at WARNING as "Unsupported language" and every file in that language indexes to zero symbols. Meanwhile `agentless-mcp capabilities` reports `probe_ok=False` for the same grammar, because `_probe` at line 306 *does* catch `ValueError`. The reported state and the runtime behaviour disagree, and the runtime behaviour is silent wrong output rather than an error. Violates "Errors surface" (a silent catch turns a crash into corruption found weeks later) and the boundary-integrity rule that foreign failures convert to typed domain values in one place.

Recommendation: wrap the `Parser(...)` construction in `get_parser` and re-raise `LanguageUnavailable` with the language name, `language.abi_version`, `pack_version()` and `cache_dir()` in the message — the same shape as line 192. Separately (cross-block) narrow `extractor.py:683` and `:727` to the `ValueError` `_grammar_of` actually raises, so a grammar failure can never be misfiled as an unsupported extension.

### B06-H2 — the warmed-state guard keys on canonical-name membership while admission keys on name-or-alias, producing a remediation that can never succeed

`src/agentless_mcp/core/grammars.py:181-187` and `:250-257`

```python
    if not pack.has_language(name):
        message = f"unknown language '{name}': not offered by tree-sitter-language-pack"
        raise LanguageUnavailable(message)

    if name not in warmed_languages():
        message = f"language '{name}' not warmed: run agentless-mcp warmup"
        raise LanguageUnavailable(message)
```

`pack.has_language` is documented in the installed package (`tree_sitter_language_pack/api.py:167`) as "Check if a language is available by name **or alias**", while `warmed_languages()` (line 166-169) is `frozenset(pack.downloaded_languages())`, which returns canonical names only. The two sets are not the same universe. Measured on the installed 1.14.3:

```
has shell True   downloaded contains shell False
pack.get_language('shell') -> <Language id=..., version=14, name=None>
grammars.get_language('shell'): LanguageUnavailable language 'shell' not warmed: run agentless-mcp warmup
grammars.warmup(['shell']) -> ok=False [('shell', False, False, "language 'shell' not warmed: run agentless-mcp warmup")]
```

`pack.available_languages()` returns 16 entries against 15 downloaded — the extra one is `shell`, an alias for the already-warmed `bash` grammar.

Failure scenario: an operator runs `agentless-mcp warmup shell`. `_warm_one` sees the name is not in `warmed_languages()`, calls `pack.prefetch(["shell"])`, which succeeds without downloading anything because the grammar is already loadable, then `_load_and_probe` → `get_language` → `LanguageUnavailable`. `_cmd_warmup` (`adapters/cli/main.py:1103-1105`) treats any degradation among explicitly-requested languages as fatal, so the command exits non-zero telling the operator to run the command that just failed. There is no input that terminates the loop. With `AGENTLESS_MCP_NO_DOWNLOAD` set, the same alias trips the hard refusal at line 251-257 — `AtlasError: refusing to download grammar 'shell'` — for a grammar that is already on disk and needs no download at all.

This is a guard keying on a correlate (canonical-name string membership) rather than on the invariant it protects (is this grammar loadable without a network fetch). The correlation breaks on aliases and the guard fails closed with unactionable advice.

Recommendation: resolve the caller's name to its canonical form once, at the boundary, and gate on the canonical name; or make the warmed check probe loadability directly instead of comparing strings. Either way, reject a name the module will not accept at argument-parsing time with the canonical spelling named, so `warmup shell` says "use 'bash'" instead of looping. Could be argued Medium — impact is a confusing failure, not data loss — but the invariant violation and the non-terminating remediation put it here.

## Medium

### B06-M1 — `_configured_cache_dir` conflates a global mutation with a query, and caches both

`src/agentless_mcp/core/grammars.py:152-158`

```python
@lru_cache(maxsize=1)
def _configured_cache_dir() -> str:
    """Apply the cache-dir override once, then report the effective path."""
    override = os.environ.get(ENV_CACHE_DIR)
    if override:
        pack.configure(PackConfig(cache_dir=override))
    return pack.cache_dir()
```

The function both mutates third-party global state (`pack.configure`) and returns data. It is called purely for the side effect at line 168 (`warmed_languages`) and line 179 (`get_language`), where the return value is discarded, and for its value at line 218 and via `cache_dir()`. That is the command/query split failing: "A function either returns data or mutates state, never both."

The `lru_cache` compounds it. Whichever call site runs first decides whether `pack.configure` is ever applied; a later `ENV_CACHE_DIR` change is silently ignored, with no error and no log. `tests/conftest.py:41` (`os.environ.setdefault(grammars.ENV_CACHE_DIR, pack.cache_dir())`) is correct today only because `warm_grammars` is session-autouse and happens to run before anything else touches the module — any future import-time or earlier-fixture call to `cache_dir()` silently drops the pinning that keeps grammar caches out of the per-test `XDG_CACHE_HOME`, and the symptom would be tests downloading into tmp dirs, not an error.

Recommendation: apply the configuration once from an explicit wiring step (the CLI/server startup path already exists) rather than lazily from a cached query, and make `cache_dir()` a pure read. That also satisfies "config and wiring errors fail at startup, not first use."

### B06-M2 — the cache-dir override crosses the boundary unvalidated and unstripped

`src/agentless_mcp/core/grammars.py:155-157`

```python
    override = os.environ.get(ENV_CACHE_DIR)
    if override:
        pack.configure(PackConfig(cache_dir=override))
```

No `.strip()`, no existence check, no writability check — the raw environment string goes straight into `PackConfig`. The repo's own convention differs: `core/cache.py:385` reads its equivalent as `os.environ.get(ENV_CACHE_HOME, "").strip()`.

Failure scenario: a shell export with a trailing newline or space, or a path typo, or a read-only mount. `pack.configure` accepts it, and the error surfaces much later and in the wrong vocabulary — `language 'python' not warmed: run agentless-mcp warmup` — which sends the operator to fix warmup instead of the misconfigured variable. This is the "config errors fail at startup, not first use" rule failing, and it is also the path where an unwritable directory turns every warmup into a permanent download attempt.

Recommendation: parse the variable once at the boundary — strip, expand, resolve, assert the directory exists and is writable — and raise a config error naming `ENV_CACHE_DIR` and the resolved path when it is not usable.

### B06-M3 — the package's only network call has no timeout and the pack offers no knob

`src/agentless_mcp/core/grammars.py:258-268`

```python
        try:
            pack.prefetch([name])
        except (pack.Error, RuntimeError) as exc:
```

`inspect.signature(pack.prefetch)` is `(languages: list[str]) -> None`, and `dataclasses.fields(PackConfig)` yields exactly `cache_dir`, `languages`, `groups` — the pack exposes no timeout, connect-timeout, or retry configuration at all. So the download has no wall-clock bound anywhere in the stack.

Failure scenario: a stalled or half-open connection to the grammar mirror (captive portal, corporate proxy that accepts and never answers) hangs `agentless-mcp warmup` indefinitely with no output, no partial report, and no diagnosis. In CI this consumes the job timeout with a log that ends mid-run. Violates "Every network or out-of-process call gets a timeout"; because the dependency offers no knob, the bound has to be imposed at this boundary or the absence has to be a recorded decision.

Recommendation: run `prefetch` under an explicit deadline at this call site (a worker thread or subprocess with a wall-clock bound) and turn the expiry into the same degraded row the `pack.Error` path already produces, with the elapsed time and the language named. Document the chosen bound where the module documents the warmup/no-fetch split.

### B06-M4 — five language tables, no gate keeping them in agreement

`src/agentless_mcp/core/grammars.py:41-66` (`TIER1_LANGUAGES`, `TIER2_LANGUAGES`, `ALL_LANGUAGES`) and `:77-93` (`_PROBE_SAMPLES`)

Language support is spread across five independently-maintained tables: `ALL_LANGUAGES` and `_PROBE_SAMPLES` here, `LANGUAGE_CONFIGS` and `TreeSitterExtractor.SUPPORTED_EXTENSIONS` in `core/extractor.py`, and `LANGUAGE_PREFIXES` in `core/symbols.py`. I checked them and they agree exactly today:

```
cfg - all []        all - ext []        probe symdiff all []
ext - all []        all - prefixes []   all - cfg ['c','cpp','python','rust']   (dedicated handlers, by design)
```

Nothing keeps them that way. The only tests are `tests/unit/test_tier2_languages.py:73-83`, and all three assert one direction for `TIER2_LANGUAGES` only:

```python
    def test_every_tier2_language_has_a_config_row(self):
        for name in grammars.TIER2_LANGUAGES:
            assert name in LANGUAGE_CONFIGS
```

`test_every_tier2_language_has_a_probe_sample` (line 85) is parameterized over `FIXTURE_FILES`, not `TIER2_LANGUAGES`, and skips on a cold pack cache, so it can assert nothing at all.

Failure scenario: a tier-1 language added to `TIER1_LANGUAGES` without a `SUPPORTED_EXTENSIONS` row. `warmup` fetches and probes it green, `capabilities` reports it `tier=1 warmed=True probe_ok=True`, and `extract_symbols` returns `[]` for every file of that language because `SUPPORTED_EXTENSIONS.get(suffix)` is `None` (`extractor.py:655-658`). The repo map is silently missing a language the tool advertises. The mirror case — a language reachable through `SUPPORTED_EXTENSIONS` but absent from `ALL_LANGUAGES` — is never warmed by the default `warmup` sweep, so it fails at first tool call rather than at warmup.

Recommendation: one test that asserts set equality across all five tables in both directions (with the four dedicated-handler languages named explicitly as the known `LANGUAGE_CONFIGS` exemption). A guarantee this module states in prose — "the tier says how much evidence stands behind the node-type table" — needs a gate, and today it has none.

### B06-M5 — hand-rolled, case-sensitive boolean parsing on the flag that decides whether warmup hard-fails

`src/agentless_mcp/core/grammars.py:161-163`

```python
def no_download_requested() -> bool:
    """True when the environment forbids fetching grammars."""
    return os.environ.get(ENV_NO_DOWNLOAD, "") not in ("", "0", "false", "False")
```

The denylist misses `FALSE`, `no`, `off`, `n`, and any value with surrounding whitespace. Every one of those reads as "downloads forbidden".

Failure scenario: an operator sets `AGENTLESS_MCP_NO_DOWNLOAD=FALSE` (or has `AGENTLESS_MCP_NO_DOWNLOAD=false ` with a trailing space from a `.env` file) intending to allow downloads. `warmup` on a cold cache then raises `AtlasError: refusing to download grammar 'bash': AGENTLESS_MCP_NO_DOWNLOAD is set. Warm it on a networked machine and copy ... across, or clear the flag`. The message is technically true and practically misleading — the operator did clear the flag, in the spelling most shells use. This is the only env-boolean in the package (`grep -rn "environ.get\|getenv" src/` returns three hits total), so there is no shared parser to reuse; the fix is a small local one.

Recommendation: parse case-insensitively after stripping, against an explicit truthy set, and reject an unrecognised value with an error naming the variable and the accepted spellings rather than defaulting it to "blocked".

### B06-L1 — the refusal raised from inside a generator discards every row already computed

`src/agentless_mcp/core/grammars.py:220`

`_warm_one` raises `AtlasError` (line 257) on the first language that needs a fetch while downloads are blocked, and because the raise happens during generator consumption, the capabilities computed for the preceding languages are thrown away. ### B06-L5 — the test module's hermeticity claim is not its own

`tests/unit/test_grammars.py:1-6` states "Nothing here reaches the network: the warmed-state probe is monkeypatched". Three tests do not monkeypatch it — `:16` (`get_language("python")`), `:56-60` (real `warmup(["python"])`), `:79-85` (`loaded_capabilities(["python"])`) — and depend on the ambient pack cache. ### B06-L6 — `get_parser` hands one shared mutable `Parser` to every caller, including thread-pool workers (measured: not a live race)

`src/agentless_mcp/core/grammars.py:196-199`. The `@cache` makes exactly one `Parser` per language for the process, and `application/validate_service.py:435` (`ThreadPoolExecutor(max_workers=request.jobs)`) reaches it through `core/normalize.py:184` (`grammars.get_parser(language)`) on every `--jobs N > 1` validate run. `tree_sitter.Parser` carries mutable C state and py-tree-sitter documents no thread-safety guarantee, and neither does this module.

I measured it rather than assuming. 8 threads × 60 parses on one shared parser produced 0 anomalies. Throughput for 4 threads on 4 private parsers (0.274s) versus 4 threads on 1 shared parser (0.291s) versus 1 thread (0.067s) shows no parallel speedup at all, so `parse()` holds the GIL on tree-sitter 0.26.0 and the sharing is safe on CPython today. Recording it as Low because the safety is incidental — it rests on the GIL, not on anything this module states or enforces, and a free-threaded interpreter removes it. Either state the contract in the docstring (`get_parser` returns a process-shared parser; safe only while `parse` holds the GIL) or make the memoization thread-local.

## Cross-block observations

- **`core/extractor.py:681-685` and `:725-729` swallow any `ValueError` from `grammars.get_parser` as "Unsupported language" and return `[]`.** The `except` is aimed at `_grammar_of`'s own `ValueError` (line 638) but catches the whole call, so B06-H1's untyped parser failure becomes a WARNING log and an empty symbol list for every file in that language. Needs fixing at both ends: typed error out of `grammars`, narrower catch in `extractor`.
- **`core/extractor.py:634-636` (`load_language`) has no callers.** `grep -rn "load_language\|get_language(" src/` finds only its own definition — a public method on the extractor that nothing uses. Dead weight for whichever block owns `extractor.py`.
- **`tests/conftest.py:32-45` downloads grammars over the network on a cold cache**, session-autouse, for the entire suite. Every block's tests inherit that. The fixture is careful about *where* the download lands but the first run is not hermetic in the sense the global rule means.
- **`tests/unit/test_tier2_languages.py:63-69` skips per language whenever the pack cache lacks that grammar**, so the whole tier-2 suite can report green having asserted nothing. Its own docstring says "cold-cache skips and a red suite must not look the same" — but nothing asserts that at least one language actually ran. A session-level check that the parameterized set was non-empty would close it.
- **`core/cache.py:491, 634, 693` call `grammars.pack_version()` as a cache-key input.** That is an uncached `importlib.metadata.version` lookup (filesystem scan of site-packages) on every index build and read, and `metadata.PackageNotFoundError` is unhandled in `grammars.py:142-144` and everywhere upstream — an install where the distribution metadata is absent but the module imports (vendored copy, `PYTHONPATH` install) crashes the `capabilities` tool with an unmapped exception instead of an `AtlasError`.
